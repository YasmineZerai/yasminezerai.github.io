I built **loopview**, a local debugger for AI agents. It receives standard **OpenTelemetry** traces and draws each run as a **live graph**: agents as groups, steps as cards, edges for sequence, parallel fan-out and fan-in, loops and handoffs. It's **published on PyPI** and runs on your machine: one process, one port, no account, no database.

## Problem

When an agent's answer is wrong, slow or expensive, the question is always **what happened**, and a flat list of spans makes you rebuild it in your head. Many debugging tools also come with one framework: switch frameworks and you switch tools.

## What I built

- **One view for every framework:** LangGraph, Pydantic AI, **CrewAI**, the **OpenAI Agents SDK** and hand-written loops, normalized into one schema.
- **Every step, opened up:** the model's thinking and the exact arguments of every tool call it made.
- **A cost tree** that shows where the tokens and dollars went, down to system prompt, tool definitions, history, cache, thinking and reply.
- **A Tools tab** that shows, across many runs, how each tool fails and what the agent did next.

## Results

- **Published on PyPI** as two packages: `loopview` (the server, which ships the built UI) and `loopview-sdk` (`connect()`, `agent()`, `@tool`), released through GitHub Actions with PyPI trusted publishing.
- **One view** for LangGraph, Pydantic AI, CrewAI, the OpenAI Agents SDK and hand-written loops, each checked against recorded traces.
- The Tools tab surfaces findings no single trace shows: over 20 tasks on GitHub's MCP server, the agents were offered **15 tools they never called**, whose definitions cost **about 138,000 tokens**.
- A [live demo](https://yasminezerai.github.io/loopview/) anyone can open in a browser, with nothing to install.

<More title="More details: how it works">

**How it works.** A Python server (FastAPI) receives OTLP traces, groups spans into runs, and a normalizer with one adapter per convention (OTel GenAI, OpenInference, plain spans) turns them into agents, steps, model calls and tool calls. Control flow comes from one rule: within the same agent, A leads to B when A ended before B started and nothing sits between them. That gives sequences, parallel fan-out and fan-in, loops and handoffs. Every 100 ms, changed steps go to the browser over **Server-Sent Events**.

**The UI** is React 19 and TypeScript, with React Flow and ELK layout in a Web Worker. Replay runs from 0.5x to 4x, with a timeline, light and dark themes, and export and import of runs.

**Runs on your machine:** one process, one port, no account, no database.

</More>
